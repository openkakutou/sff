# Module: wasm
**Role:** `cmd/wasm` is the library's WebAssembly entrypoint (backlog item 004): thin `syscall/js` glue exposing the root package's `Load` and `ResolveSpritePixels` (see `modules/root.md`) to a browser or any JS host as global functions, so `stage`/lifebar consumers can load and decode a `.sff` sprite sheet without a Go toolchain of its own — built and released independently of `character`'s own WASM build, even though both wrap the same underlying `sff` functions. It carries no logic beyond argument conversion, calling into the root package, and marshaling results to JS — all real behavior lives there, unit-tested independently.
**Files:** `cmd/wasm/main.go`, `cmd/wasm/smoke.mjs`
**Exports (JS, not Go):**
- `globalThis.OpenKakutouSff.load(sffBytes)` — one `Uint8Array` argument, returns `{ spriteGroups: string|null, error: string|null }` (exactly one non-null) — `spriteGroups` is a JSON `[]SpriteGroup`, metadata only, never decoded pixels
- `globalThis.OpenKakutouSff.resolveSprites(sffBytes, requests, overrideBytes)` — `sffBytes` a `Uint8Array` (transferred once for the whole batch), `requests` an array of `[group, image]` pairs, `overrideBytes` an optional `Uint8Array` (`undefined`/`null` means no override; any other value, including empty, is decoded and its own validation errors apply to every request in the batch); returns one `{ pixels: Uint8Array|null, width, height, error: string|null }` per request, `pixels` a flat row-major straight-alpha RGBA buffer

**Depends on:** `modules/root.md` (`Load`, `ResolveSpritePixels`, `DecodeExternalPalette`)

**Design decision:** `main.go` is build-tag gated (`//go:build js && wasm`), so it is invisible to a normal host `go build ./...`/`go test ./...` — only `GOOS=js GOARCH=wasm go build ./cmd/wasm` compiles it. Both exposed functions never let an internal panic escape to the JS caller (a `recover()` at each callback boundary reports it as `error` instead — for `resolveSprites`, a panic before results are built falls back to a bare `nil` return rather than a well-formed per-request array, mirroring `load`'s own recovery) and never leave the module in a broken state after an error — the next call is handled independently. `resolveSprites` is batched and stateless — one call resolves many sprites from one `sffBytes` transfer, parsing the file fresh each call rather than keeping Go-side session state across calls — and reports a sprite that doesn't exist with a stable `"sprite not found: "` error prefix. This whole API shape deliberately mirrors `character`'s own already-shipped `cmd/wasm` contract (same global-per-package convention, same result-shape discipline); the release pipeline that publishes this module additionally gates on a real smoke test of the built artifact before publishing, which `character`'s own pipeline does not do. See `.vibe/decisions/003-wasm-entrypoint-api-shape-and-release-smoke-gate.md`. `smoke.mjs` is a Node.js verification harness (loads the built `.wasm` via `wasm_exec.js`, the same way a browser would) — it is not a `go test` file since `syscall/js` code cannot run under the plain Go toolchain, and doubles as a minimal JS usage example for both globals. See `docs/wasm.md`.
