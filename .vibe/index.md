## Modules
- [`modules/root.md`](modules/root.md) — package `sff`: full read/write support for MUGEN/Ikemen GO `.sff` sprite sheet files (v1 and v2), including palette resolution and external `.act` palette overrides — migrated from `character/sff` (backlog item 001), no dependency on `character`; `EncodeV2Sprite` now also encodes the v2 RLE8 and LZ5 compressed pixel formats (backlog item 002), completing their read+write cycle; RLE5 decode+encode (backlog item 006) is also implemented now, ported directly from Ikemen-GO's reference algorithm — but, unlike every other format, never validated against a real file (see decision `014`); the palette write path is now complete too (backlog item 003): `EncodeV1Palette`/`EncodeV2Palette`/`EncodeExternalPalette` re-encode a `Palette` back to each on-disk format, and `(*Palette).SetColor` is the validated entry point for editing a color from caller-supplied integers
- [`modules/wasm.md`](modules/wasm.md) — `cmd/wasm`, this repo's own WebAssembly entrypoint (backlog item 004): build-tag-gated `syscall/js` glue exposing `Load` and `ResolveSpritePixels` as JS-callable globals (`OpenKakutouSff.load`/`.resolveSprites`), mirroring `character`'s own `cmd/wasm` contract but built and released independently, verified by a Node.js smoke harness since `syscall/js` code cannot run under the plain Go toolchain

## Observed patterns
- Tests are co-located with source as `*_test.go`, one behavior per test function, named `Test<Subject>_<Expectation>` — one test file per source file
- Read-path shapes that a parser needs more than the shared model can hold (file offsets, on-disk linking/sharing fields) get their own version-specific low-level type (`V1SpriteTable`, `V2SpriteTable`, `PCXImage`, `V2Image`) rather than being forced onto `Sprite`/`SpriteGroup`
- Write-path functions (`SerializeV1`, `SerializeV2`, `EncodePCX`, `EncodeV2Sprite`) take their own write-only input types (`V1WriteSprite`, `V2WriteSprite`/`V2WritePalette`) carrying real bytes to embed, mirroring the read-path split
- Round trips are semantic (serialize → re-parse → re-decode → compare), not byte-exact — `.sff` is binary with no diff-friendliness benefit to preserving an original file's exact layout; `EncodeV2Sprite`'s RLE8/LZ5 encoders follow the same rule, targeting "decodes back to the same pixels" rather than byte-for-byte reproduction of any particular original encoder's output — the LZ5 encoder specifically only ever emits literal runs, never back-reference copies, favoring straightforward correctness over compression ratio (see an explicit ADR)
- Decoders/encoders are validated against real, unmodified community files vendored as trimmed fixtures under `testdata/` (see `testdata/README.md`), not only hand-built synthetic data — this repeatedly caught real-file bugs synthetic data missed; this also caught a pre-existing fixture-naming quirk (`testdata/files/v2-rle8.sff`'s one sprite is actually LZ5-encoded, not RLE8 — `v2-empty-palette-use-first.sff` is the fixture that genuinely carries a real RLE8 sprite)
- Every format is validated against real, unmodified fixtures before being trusted, except one deliberate exception: v2's RLE5 pixel format (both decode and encode) was implemented (backlog item 006) by porting Ikemen-GO's reference algorithm directly rather than reconstructing it from memory, but no real RLE5-encoded file has ever been found to validate it against — see decision `014` for the accepted gap and what to do if one ever surfaces
- `ResolveSpritePixels` is the one-call combinator most consumers are expected to use: parse + decode + palette-resolve in one call, given a file and a `(group, image)` reference
- Stdlib-only: `go.mod` declares no dependencies
- `cmd/wasm` is the one package gated by a Go build constraint (`//go:build js && wasm`) rather than by directory convention alone, keeping `syscall/js`-only code out of a normal host `go build ./...`/`go test ./...`; its own correctness is instead verified by a Node.js script (`smoke.mjs`) loading the built module the way a real browser would. The tagged-release workflow (`.github/workflows/release.yml`) gates publishing the built `sff.wasm`/`wasm_exec.js` pair on that same smoke test passing against the exact built artifact, not just a successful native build — see `.vibe/decisions/003-wasm-entrypoint-api-shape-and-release-smoke-gate.md`.
