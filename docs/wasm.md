# WebAssembly entrypoint

`cmd/wasm` builds the library into a WebAssembly module a browser (or any
JS host) can load directly — no local Go toolchain needed. It is thin glue
only: all real logic lives in the root `sff` package (see
[docs/api.md](api.md)), which is unit-tested independently of this file.

## Building locally

```sh
GOOS=js GOARCH=wasm go build -o sff.wasm ./cmd/wasm
cp "$(go env GOROOT)/lib/wasm/wasm_exec.js" .
```

`cmd/wasm/main.go` is build-tag gated (`//go:build js && wasm`), so it is
invisible to a normal host build/test — `go build ./...` and `go test ./...`
never touch it.

## JS API

The module registers a single global on `js.Global()`:

```js
globalThis.OpenKakutouSff.load(sffBytes)
```

- **Arguments**: one `Uint8Array` — the raw bytes of a `.sff` file (v1 or
  v2, auto-detected), already fetched or selected by the caller.
- **Return value**: always a plain object `{ spriteGroups, error }`,
  exactly one field non-`null`:
  - `spriteGroups` — a JSON string of `[]SpriteGroup` (see
    [docs/api.md](api.md#key-types)): every sprite in the file, grouped,
    with dimensions, axis (pivot) point, and palette reference — metadata
    only, never decoded pixel/color data.
  - `error` — a descriptive message (e.g. an unrecognized file signature,
    or the reason the call itself was malformed, such as a wrong
    argument count).
- The function never throws: an internal panic is recovered at this
  boundary and reported as `error` instead of crashing the whole page's
  WASM instance. A prior error does not leave the module in a broken
  state — the next call is handled independently.

### Example

```js
const result = globalThis.OpenKakutouSff.load(sffBytes);
if (result.error) {
  throw new Error(result.error);
}
const spriteGroups = JSON.parse(result.spriteGroups);
```

## Resolving sprite pixels

`load`'s JSON only carries sprite *metadata* — never decoded pixel/color
data. A second global resolves a sprite's actual on-screen image:

```js
globalThis.OpenKakutouSff.resolveSprites(sffBytes, requests, overrideBytes)
```

- **Arguments**:
  - `sffBytes` — a `Uint8Array` of a `.sff` file's raw bytes, transferred
    once for the whole call, not once per sprite — batch several requests
    together (e.g. every sprite in a sheet) rather than calling this once
    per sprite, which would re-transfer the whole file each time.
  - `requests` — an array of `[group, image]` number pairs, one per sprite
    to resolve.
  - `overrideBytes` — optional. `undefined` or `null` means "use each
    sprite's own palette". Any other value, including an empty
    `Uint8Array`, is decoded as an external `.act` palette file and applied
    to every sprite in the batch in place of its own; an invalid value
    (wrong size, etc.) is reported as an error for every request, never a
    silent fallback to each sprite's own palette.
- **Return value**: an array with one result object per request, in the
  same order, shaped `{ pixels, width, height, error }` — exactly one of
  `pixels`/`error` is non-`null` (`width`/`height` are `0` on error, not
  `undefined`):
  - `pixels` — a flat, row-major `Uint8Array` with straight (non-
    premultiplied) alpha, `width * height * 4` bytes (RGBA per pixel) —
    directly usable as `new ImageData(pixels, width, height)`.
  - `error` — a descriptive message. A request naming a sprite that
    doesn't exist is prefixed `"sprite not found: "`, distinguishable from
    every other failure (malformed `sffBytes`, corrupt pixel/palette data,
    an implausibly large declared sprite size) — useful when probing
    candidate sprites, e.g. while browsing a sheet.
- Like `load`, this never throws — an internal panic is recovered and, since
  the panic could occur before results are built, may report as a bare
  `null` return rather than a well-formed per-request array; a prior error
  does not leave the module in a broken state.

See
[`.vibe/decisions/003-wasm-entrypoint-api-shape-and-release-smoke-gate.md`](../.vibe/decisions/003-wasm-entrypoint-api-shape-and-release-smoke-gate.md)
for why the API is shaped this way (mirroring the sibling `character`
project's own WASM entrypoint contract) and why the release pipeline below
adds a check `character`'s own workflow doesn't have.

### Example

```js
const results = globalThis.OpenKakutouSff.resolveSprites(sffBytes, [[0, 0], [0, 1]], null);
for (const { pixels, width, height, error } of results) {
  if (error) {
    console.warn(error);
    continue;
  }
  const imageData = new ImageData(new Uint8ClampedArray(pixels.buffer), width, height);
  canvasContext.putImageData(imageData, 0, 0);
}
```

## Verifying a build

`cmd/wasm/smoke.mjs` is a Node.js harness that loads a built module the same
way a browser would (via `wasm_exec.js`) and exercises both the nominal path
and error paths — the closest thing to `go test` this file has, since
`syscall/js` code cannot run under the plain Go toolchain:

```sh
node cmd/wasm/smoke.mjs [path/to/sff.wasm]  # defaults to ./sff.wasm
```

## Release pipeline

`.github/workflows/release.yml` runs on every pushed tag matching
`v[0-9]*.[0-9]*.[0-9]*` (e.g. `v1.2.3`). It builds and tests the module
normally first (`go build ./...`, `go test ./...`, `go vet ./...`) — nothing
is published if any of those fail — then builds `sff.wasm` and copies the
matching `wasm_exec.js`. Before publishing, it also runs `cmd/wasm/smoke.mjs`
against the exact just-built `sff.wasm` bytes on a pinned Node.js version,
gating the release on a real, working WASM artifact rather than only a
successful native build — a check the sibling `character` project's own
release workflow does not have (see the ADR linked above). Only then does it
publish both files as assets on that tag's GitHub Release under stable,
predictable names. `wasm_exec.js` is Go-version-specific glue; the workflow
always builds and copies it from the same Go toolchain install that produced
the `.wasm`, so the two published files are guaranteed to be a matched
pair — a consumer should always fetch both from the same release, never mix
versions, and never mix them with another repo's own `sff.wasm`/
`wasm_exec.js` pair either.
